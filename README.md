# Conservation Planning Tool — Victoria, Australia

A local interactive web application for spatial conservation prioritisation in Victoria, Australia. It offers two integer-programming formulations, species selection, upload of additional species-distribution rasters, and map-based comparison of optimisation results.

The application was developed for a supervised student project. It uses the **Victoria data** from `jeffreyhanson/robust.prioritizr.data` (v1.0.0); the datasets are **downloaded at runtime**, not bundled with this repository. The original optimisation notebook was provided by the project supervisor; the app adapts these formulations for web interaction.

## Features

- **Minimum Set**: minimise total planning-unit cost while satisfying each selected species' conservation target. This formulation does **not** use a budget.
- **Minimum Shortfall**: minimise the sum of unmet species targets, subject to a maximum total-cost budget.
- Adjustable global conservation target (1–100%).
- Search and select from the **1990 baseline** species layers (1,046 layers in the dataset version tested).
- Add an additional species via a validated single-band GeoTIFF aligned with the Victoria cost raster; it is then available for selection.
- View selected planning units as GeoJSON polygons on a Leaflet/OpenStreetMap map.
- Compare the two most recent successful runs using a table and four bar charts.
- Display backend timing breakdown (data preparation, model construction + solver call, GeoJSON generation, total processing time).

## Requirements

- Windows with **Python 3.13** recommended (the supplied project environment used Python 3.13).
- Internet access to download the four Victoria source files from GitHub and Leaflet/OpenStreetMap resources.
- An installed, usable **Gurobi** solver and valid license (an academic license may be available). `gurobipy` is installed by the requirements file, but a working solver license must be configured separately. See https://www.gurobi.com/ and https://pyomo.readthedocs.io/.

Run commands below in **PowerShell**, from the project root (the directory containing `backend/` and `frontend/`).

## Install

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

If your PowerShell policy blocks the activation script, you can call `.\.venv\Scripts\python.exe` directly instead of activating it.

Check your Gurobi license and that `SolverFactory("gurobi")` is available before running full optimisations.

## Run locally

Terminal 1, in the project root:

```powershell
python -m uvicorn backend.app:app --reload
```

Open the interactive API documentation at http://127.0.0.1:8000/docs.

Terminal 2, in the project root:

```powershell
cd frontend
python -m http.server 5500
```

Open the application at http://127.0.0.1:5500. The frontend assumes the backend is running on port `8000`. Keep both terminals running. If you change host or ports, update `API_BASE` in `frontend/app.js` and allowed origins in `backend/app.py`.

**Important:** The server loads source rasters and species metadata *on startup*, so starting the API requires access to the configured GitHub release URLs. The first request may also take time to read raster bands.

## Usage

1. Choose **Minimum Set** or **Minimum Shortfall**.
2. Set a conservation target. For Minimum Shortfall, also set an available budget. **Costs are opportunity-cost index units, not AUD.**
3. Select species. By default, all original baseline species are selected; previously uploaded species are not automatically selected on a fresh page load.
4. Click **Run Optimization** to compute the solution and display the selected planning units on the map.
5. Change settings and run again. The comparison section shows two successful scenarios; the map shows the latest scenario. Comparison history is only held in browser memory and clears on refresh.

### Adding a species

Expand **Add new species (GeoTIFF)**, enter a species name and upload a `.tif` or `.tiff` file. Uploaded rasters must:

- contain exactly **one** numeric band, at most **50 MiB** in upload size;
- match the Victoria cost raster's CRS, transform, width and height exactly;
- contain at least one positive value in a valid planning unit.

Values greater than zero represent presence; zero, negative values and masked/nodata pixels represent absence. Uploaded species are registered locally under `backend/uploaded_species/`, with filenames generated by the server. The directory is created automatically on first upload.

**Uploads are data, not source code.** They are intentionally excluded from the clean submission package. Back up the upload directory separately if you want to preserve your own imported layers. The provided UI does not include a remove-upload button; do not manually delete registry entries unless you understand the consistency implications.

## API

| Endpoint | Purpose |
|---|---|
| `GET /` | Health message |
| `GET /species` | Baseline species and registered uploaded species |
| `GET /species/uploads` | Uploaded species list only |
| `POST /species/upload` | Multipart form with `name` and one-band GeoTIFF `file` |
| `POST /optimize` | Optimise a selected scenario |

Example Minimum Set request:

```json
{
  "formulation": "min_set",
  "target_pct": 0.3
}
```

Example Minimum Shortfall request:

```json
{
  "formulation": "min_shortfall",
  "target_pct": 0.3,
  "budget": 16255.78
}
```

Optional `selected_species` is an array of IDs from `GET /species`. Omitting it uses **all baseline species only**. If supplied, it must be non-empty; it can mix baseline and uploaded IDs. Invalid IDs and missing required budgets are rejected with HTTP 422.

The `/optimize` response includes formulation, selected planning-unit count, total cost, number of species meeting their targets, total shortfall, selected-unit GeoJSON, and server-side timings (seconds).

## Models

Let `x_i ∈ {0,1}` indicate selection of planning unit `i`, `c_i` its cost, `a_ij = 1` if species `j` is present there and `t_j` its coverage target.

**Minimum Set** minimises `Σ_i c_i x_i` subject to `Σ_i a_ij x_i ≥ t_j` for every selected species `j`.

**Minimum Shortfall** minimises `Σ_j s_j` subject to `Σ_i a_ij x_i + s_j ≥ t_j`, `s_j ≥ 0`, and `Σ_i c_i x_i ≤ budget`.

Targets use `ceil(target_pct × number_of_valid_planning_units_containing_species)`; presence is binary. All species have equal weights in the Shortfall objective. The model does not implement additional connectivity, spatial clustering or protected-area constraints; although the code opens `pa.tif`, that raster is not used in the current optimisation constraints.

## Basic validation

For the baseline species set, use `target_pct = 0.3` and compare against the supervisor's rerun notebook. In a previous verified run on the same source data:

| Metric | Minimum Set | Minimum Shortfall (budget 16255.78) |
|---|---:|---:|
| Species evaluated | 1046 | 1046 |
| Planning units selected | 3935 | 2751 |
| Total cost (cost units) | approximately 32511.67 | approximately 16255.37 |
| Species meeting targets | 1046 | 419 |
| Total shortfall | 0 | 483192 |

The precise selected units may differ across solver versions or alternative optima. For a final demonstration, also test (i) one/two selected species; (ii) incorrect/missing budgets; (iii) a misaligned GeoTIFF; (iv) two successful runs and the comparison charts. A full fresh-install and Gurobi end-to-end test has not been conducted in the review environment.

## Limitations and considerations

- Intended for **local supervised use**, not as a production public upload service: no authentication, accounts or rate limits are implemented.
- Existing raster datasets are fetched from external URLs at startup; there is no bundled/offline mode or automatic source-data version comparison.
- The frontend's comparison is descriptive. Different objectives, budgets, targets or species selections may make raw results not directly comparable as measures of which solution is preferable.
- `solver_seconds` measures **model construction and solver call together**, not the solver's internal optimisation time alone; `total_seconds` is server processing time excluding the network.
- Map base tiles depend on OpenStreetMap availability; selected-unit polygons are calculated by the backend.
- No packaged `Gurobi` license or raw source datasets are included.
